How this skill works, in three diagrams

This skill turns ONE terminal into the orchestrator. The orchestrator doesn't build: it splits your request into pieces, hands them to others, and checks what comes back before letting it in.

  • Green: what moves forward
  • Red: the lock that blocks
  • Gray: what waits or helps

Inside the diagrams there isn't a single command or path: just plain words. The commands and files are in the table below each diagram.

Why some are red and others gray: today only locks 1 through 6 block the way. 7 through 10 are written laws the AI follows, with an alert that reminds it. Saying they all block would be promising a brake that doesn't exist.

Diagram 3 — What happens on its own, with nobody asking

You're looking at two clocks running at the same time, never touching each other: a lead's, and the orchestrator's.

While a lead is working
Memory halfway full writes its note
Memory almost full compacts itself
Stays the SAME terminal and rereads its note
When it finishes cleans up its own mess
While the orchestrator is working
Every 5 minutes it looks at waits, deliveries, and overlaps
And it hunts orphan processes: it only warns
If it compacts itself its note reaches it
The note lists the new receipts
Almost every alert is for the AI
When a lane closes old notes get cleaned up
